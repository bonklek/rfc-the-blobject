# What is the conclusion?

## 23. Conclusion

The Blobject proposes purchaser-selected Ethereum serving durations. With the same publications and durations no longer than a common baseline, shorter leases cannot increase logical retained stock or required byte-time. This is an accounting result. It does not establish a physical saving, a safe minimum duration, or an economic case for changing Ethereum.

The minimal mechanism attaches a lease to each blob publication, starts its clock at inclusion, bounds admitted obligations, and ends the serving duty at expiry. Reclamation may take longer. Publication-time availability and permissionless reconstruction remain requirements; stronger proof-of-service enforcement is a separate design. A conservative deployment must retain a full-service option whose exact boundary matches the current epoch-inclusive serving rule.

The first decisive experiment belongs under current 1D PeerDAS: compare fixed retention, a small maturity menu, and arbitrary epoch choices using the same data, recovery requirements, and hardware. Measure whether sparse historical serving releases useful resources after accounting for metadata, traffic, repair, and reclamation costs. Test application recovery timelines alongside it. A few durations may capture the value without the complexity of arbitrary choices.

Shorter leases cannot remove initial propagation or write costs, make inadequate recovery assumptions safe, or guarantee honest-user access during overload. If those constraints erase the practical benefit, the proposal should be narrowed or abandoned. A failed future 2D transition, private market, or specialized provider scheme rejects that branch, not necessarily selectable native service.

External archives, proofs over retained copies, future reservations, and specialized services may compose with this mechanism. They do not supply the missing evidence for it. The next contribution should make the core experiment more decisive rather than enlarge the feature set.
